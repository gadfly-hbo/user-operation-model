# 匹配口径对照：新内核 vs 抖音工具旧口径

> P1 交付 · 2026-11-27 · 相关：[内核口径](match-kernel.md) · [P1 规格 §5](../openspec/changes/tool1-match-kernel/spec.md)

## 1. 为什么会有口径变化

抖音工具的评分规范（`~/工作/抖音货渠匹配/货渠匹配度评分算法规范_Agent专用版.md`，只读参考）里有三个已知缺陷，产品讨论稿 §4.1 要求首版修掉：

| 旧口径 | 问题 | 新内核 |
| --- | --- | --- |
| 地域同频、品类共振两个维度**写死 85 / 84** | 占位分，不是真实计算 | 换成**城市等级**、**预测人生阶段**两个真实维度 |
| 分布距离用 L1 曼哈顿距离 | 对分布形状不敏感 | `0.60 × JS 相似度 + 0.25 × 余弦相似度 + 0.15 × Top3 重合度` |
| 权重与门槛硬编码在代码里 | 不可校准、不可审计 | 全部进 `MATCH_CONFIG`，加载期校验 |

因此**新旧总分不会逐字相等**，这是口径变化的必然结果，不是实现缺陷。

## 3. 两条评级上移的解释

- **G3 B → A（78.2 → 87.7）**：旧口径里「地域同频 85」「品类共振 84」两个占位分占 30% 权重，把总分压在 80 分线下；新口径换成**城市等级 94.4**（该渠道一二线占比高，与长羽绒服的城市结构接近）与**预测人生阶段 85.9**，同时年龄段由 L1 口径的旧值升到 81.2。
- **G4 C → B（59.2 → 68.9）**：同样受益于城市等级 87.8、人生阶段 72.1 的真实计算；客单维度 68、惩罚 -4.0 与旧工具**逐字一致**，说明差异不在客单口径。

两处上移都来自**占位分被真实维度替换**，方向一致（真实计算比固定 85/84 更贴近实际差异）。**这两处变化尚未用成交数据校准**（Q4：缺少售罄率与正匹配标签），因此按工程规范 §9.3 记为「口径已调整」，**不得表述为「已优化」**。

## 4. 输入管线忠实性

五条用例的**客单承接维度分与全局惩罚与旧工具逐条一致**（92/95/93/68/32；0/0/0/-4.0/-10.5），且五条单价均由零售额 ÷ 零售量核算得出。这说明：

- 画像归一化（六维投影、年龄归并、消费能力标签）忠实于源数据；
- 价格核算与渠道消费力提取忠实于旧工具口径。

**新分数与旧分数的差异只来自评分公式与维度集合，不来自数据处理。**

## 5. 验收口径（2026-11-27 用户确认）

| 规则 | 说明 |
| --- | --- |
| 锚点 | G1 必须为 A、G5 必须为 C |
| 新基线 | 五条新总分冻结为回归断言，实现变化必须重新核对 |
| 客单 | 客单维度分与惩罚必须等于旧值 |
| 新旧对照 | 本表随口径变化更新，不覆盖历史记录 |

回归方式：

```bash
UOM_REFERENCE_ROOT="$HOME/工作/抖音货渠匹配/product/数据输入" npm run test:golden
```

脚本在缺参考数据时**明确失败**（不跳过），并打印输入文件 SHA-256 清单作为快照证据。CI 不运行该脚本（无真实数据），结果记 `NOT_RUN`；本地运行证据见 [P1 实施记录](../openspec/changes/tool1-match-kernel/result.md)。
