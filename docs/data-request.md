# 数据补齐需求清单（给业务侧）

> 2026-11-27 · 人群运营模型项目组
> 用途：按本清单导出并提供数据文件。**导出保持原样**（不预先清洗、合并、改名），放到约定目录即可。
> 注意：其中 7 类数据（品牌/竞品画像、漏斗、会员特征、Cohort、Recency、流转矩阵、三大诊断）对应的查询能力**尚未实现解析器**，文件到位后我们还需要一轮开发才能用上；其余数据（渠道/单品画像、经营指标、关联表）到位即可被现有工具识别。
> 说明：所有数据只留在本机，不上传、不进代码仓库、不进 CI。

## 怎么给

1. 按下面各项的「放到哪」把文件放进项目 `data/` 对应目录（目录不存在就新建）。
2. 月份**优先给单月**（如 `2026-10`）；给区间（如 `2025-07~2026-06`）也能用，但会标注为近似口径。
3. 文件命名里**带上实体名和月份**（沿用你们现有导出的命名习惯即可，工具两种都认）。
4. 给完后在 `data/README.md` 的「数据时间范围声明」表里填上覆盖月份、渠道范围、商品范围、已知缺失（四项都要填，缺什么写什么）。

## 需要业务侧确认的口径（不要猜，请回话）

1. **售罄率、退货率、退款率、毛利率** 用《指标字典-品牌经营业务》里的哪几条指标编码？（字典有 945 条定义，我们按编码取数，避免口径分歧）
2. **新老客** 的判定口径（首购时间窗？跨店是否算新客？）
3. **画像月份** 能否给单月导出？若只能给区间，请说明区间含义（滚动 12 个月？自然年？）
4. **天猫侧无 TGI** 是导出限制还是平台不提供？（影响跨平台可比性分级）
5. **渠道经营指标里缺的列**（如流量成本）是「没有」还是「不给」？（「没有」我们按缺失处理，「不给」我们按不可用处理，两者在界面上的说法不同）

## 我们这边收到数据后做的事（不需要业务侧参与）

- **为 7 类未实现的数据写解析器与查询实现**（品牌/竞品画像、生命周期漏斗、会员特征字典、Cohort 留存、老客 Recency、跨渠道流转矩阵、三大诊断）：当前这 7 个工具是占位实现，文件到位也不会自动可用
- 新标签/新维度登记进映射表（跨平台映射逐条可追溯，不自动推断）
- 实体别名目录接入归一化层（修复「200 个渠道只有 1 个能关联画像」的断链）
- 跨文件冲突显式映射表（同款多平台画像不一致时不隐式合并）
- `data/README.md` 时间范围声明在索引构建时生效
- 商品 ↔ 渠道关联表接入「按渠道筛商品」与渠道级错配排序
- 逐工具验证就绪状态并回归
