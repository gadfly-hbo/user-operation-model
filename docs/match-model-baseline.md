## 3. 两组数字的差异来源

合规基线**不低于**原特征集基线（Top1 +0.0797、Top3 +0.0145、Share MAE −0.0066），
差异来自三处，均可复核：

1. **留出集缺少白名单字段**。归档 v0.4 的 24 款留出商品里，`category`／`subCategory`／`season`／
   `productLifecycle`／`ipCollaboration`／`specialFunctionOrMaterial` **全部为空**
   （原始 `product_attributes.jsonl` 如此，非抽取丢失）。因此合规模型在留出集上
   实际只用得到**版型 + 面料**；训练侧却有 73/83 款带品类等字段。
2. **FAB 文本是噪声源**。原特征集从 FAB 长文本里抽风格／功能／场景词，
   在 83 行样本上属于高维稀疏特征（交叉特征 94 个、总特征 156 个），容易过拟合。
   合规特征集特征更少（交叉特征 42 个、总特征 117 个），在留出集上泛化更稳：
   `八大消费群体` Top1 由 0.3478 升到 0.6957，`城市等级` Top1 由 0.3478 升到 0.3913。
3. **合规模型在缺失字段上退化为先验**。留出集上缺失字段恒为 0，使模型更靠近训练集的总体分布，
   这对占比集中的维度有利（`预测消费能力` Share MAE 由 0.0499 降到 0.0419），
   对区分度高的维度略不利（`预测性别` Share MAE 由 0.1512 升到 0.1629）。

## 4. 两组基线的定位

- **原特征集基线只作移植忠实性对照**。它包含 `FAB`（人工卖点），按工程规范 §9.2
  **不得进入生产预测路径**；它的作用是证明「移植的 v0.4 管线没有算错」——
  归档工件登记的三数字在本项目上以容差 0 复现（`npm run test:fidelity-v04` 第一组断言）。
- **合规基线才是生产门门槛**。生产模型（用户数据上重训）必须在该跨期协议下
  **不低于 0.7754 / 0.9300 / 0.0759**。
- P2 规格 §10 的预期是「合规基线数字会比 0.6957 低（FAB 是有信息量的特征）」；
  **实测结果与该预期相反**（合规基线更高），原因是归档留出集缺失白名单字段（见 §3.1、§3.2）。
  该差异不构成放宽验收——生产门仍以冻结的合规基线为准。

## 6. 限制与未验证项

- 两个基线都建立在**归档数据**上（23 款留出、83 行训练），样本量小，属小样本结论。
- 合规基线是在**留出集缺白名单字段**的口径下测得的，**不能外推到**「字段齐全的留出集」；
  用户真实数据到位后必须按同一协议重算并重新冻结（见 P2 规格 P2-13）。
- 归档的 LOO alpha 选择指标在数值上无效（其回代用错三角，见
  `packages/tool2-portrait-predict/src/pipeline/03-select-alpha.ts` 文件头）；
  本项目改用唯一 Cholesky 求解器后 LOO 数值与归档不同，但**选中 alpha 仍为 50**，
  且最终三数字不受影响（最终模型不走 LOO 路径）。
- 温度校准与最终训练共用训练集的 LOO 折，属训练集内使用，可能高估置信度校准
  （归档 `worker-handoff.md` 已记录同一风险，本项目沿用该口径未改）。

### 7.3 门槛结论（如实记录，未放宽）

| 门槛 | 结论 | 依据 |
| --- | --- | --- |
| 门槛 1：六维 JS 提升全为正且符号检验全显著 | **FAIL** | 人生阶段提升为负（−0.0018，p=0.8358） |
| 门槛 2：高变异维度（购买力／人生阶段／性别）至少 2/3 显著为正 | **FAIL** | 仅购买力显著（1/3） |
| 门槛 3：相对对照组有增益 | **PASS** | 对照组 `C0_fit_fabric` 宏平均提升 0.0028 < 0.0096 |
| 门槛 4：各折 JS 提升均值为正 | **FAIL** | 人生阶段折均值为负 |
| 门槛 5：冻结输入与 fail-closed | **PASS** | 阶段 06 的 12 条校验全部 pass |

**结论口径**：v0.6 管线本身（六阶段、冻结 folds、折内基线、符号检验门槛、
fail-closed 校验）已跑通并通过；但**§9.2 合规特征集下的模型未达 v0.6 验收门槛**。
这是本轮如实记录的事实，**不得**被表述为「v0.6 验收通过」。

### 7.5 限制

- 93 款、单账号、单季度，无同平台内时间留出；结论属小样本。
- 基线 JS 已达 0.9092（单账号人群高度同源），绝对提升幅度天然很小。
- **折的分层键用了人工字段**（归档 `categoryGroup x genderCorrected`）；该字段只在**已冻结的划分结果**里，
  不进入预测路径。重做分层会改动全部 OOF 数字，属另立变更范围（见 result.md §8 范围外发现）。
- **V12 的「折内 ≠ 全量」判定条件**（二轮复核建议项 4，`06-validate.ts`）：某维度折内均值与其
  **自身**全量均值相等时（画像恒定／巧合等值），该维度单独无法区分折内与泄漏——只把等值维度
  记录进 V12 detail、不判 fail（折内性由其余「折内 ≠ 全量」的维度证明）；**整折所有维度**都等值
  （折内性完全无法证明）才 fail（fail-closed）。
- 用户真实数据到位后须按同一协议重算并重新冻结（P2-13）。
