# 匹配内核口径与工具1 用法

> P1 交付 · 2026-11-27 · 相关：[工程规范](engineering-workflow.md) · [产品讨论稿 §7.4](产品讨论稿-v0.1.md) · [P1 规格](../openspec/changes/tool1-match-kernel/spec.md) · [口径对照](match-calibration.md)

## 1. 内核在哪、怎么用

匹配内核实现于 `packages/core/src/match/`，是**工具1（事实画像入口）与工具2（预测画像入口共用**的唯一评分实现：

| 模块 | 职责 |
| --- | --- |
| `types.ts` | 内核输入输出契约（`MatchInput` / `MatchResult`） |
| `config.ts` | **参数单一来源**（`MATCH_CONFIG`）与加载期校验 |
| `kernel.ts` | `scoreMatch`：六维评分 → 综合分 → 评级 → 驱动因素 |
| `portrait-input.ts` | 统一投影 → 内核输入的转换（`toMatchPortraitInput`） |
| `price.ts` | 真实成交单价解析单一来源（`resolveUnitPrice` / `resolveRetailAmount`） |
| `../period/` | 期间模型与画像选择（`parsePeriod` / `periodCovers` / `selectPortrait`）：月份写法、覆盖判定、多月份／多平台歧义显式返回的唯一来源（切片 A 起，原 `month.ts` 并入） |

```ts
import { scoreMatch } from '@uom/core';

const result = scoreMatch({
  spu: 'SPU-2601',
  channelId: 'live:森马官方旗舰店',
  month: '2026-10',
  product: productPortrait,   // 统一维度投影 + 占比
  channel: channelPortrait,
  price: 318.69,              // 真实成交单价；缺失传 undefined
});
```

同输入必同输出；内核不读文件、不发网络请求。

## 2. 评分公式

```
单维度分 = 100 × (0.60 × JS 相似度 + 0.25 × 余弦相似度 + 0.15 × Top3 重合度)
综合分   = Σ(维度分 × 权重) / Σ(可用维度权重) + 客单惩罚      → 四舍五入 1 位小数 → 裁剪到 [25, 99.5]
评级     = A（≥ 80）｜B（60–79.9）｜C（< 60）
熔断     = 总分 < 45（只做显示标记，不改变评级）
```

维度权重（讨论稿 §7.4 初值）：

| 维度 | 名称 | 权重 | 评分来源 |
| --- | --- | ---: | --- |
| `gender` | 预测性别 | 0.10 | 画像分布 |
| `age` | 预测年龄段 | 0.20 | 画像分布（5 档统一龄段） |
| `spending_power` | 消费能力 | 0.15 | 客单承接表（价格 × 渠道高／低消占比） |
| `city_tier` | 城市等级 | 0.10 | 画像分布 |
| `strategy_segment` | 策略人群 | 0.25 | 画像分布 |
| `life_stage` | 预测人生阶段 | 0.20 | 画像分布 |

**权重未经真实业务数据校准，只能记「已调整」，不得称「已优化」**（工程规范 §9.3）。待补齐成交与售罄数据后另立校准变更。

## 3. 客单承接（消费能力维度）

消费能力维度不按分布相似度计算，而是按**价格带 × 渠道消费力**判定，并给出全局惩罚：

| 价格区间 | 渠道消费力条件 | 维度分 | 全局惩罚 |
| --- | --- | ---: | ---: |
| `< 100` | 无条件 | 95 | 0 |
| `100–199.99` | 无条件 | 88 | 0 |
| `200–399.99` | 高消费占比 ≥ 28% | 92 | 0 |
| `200–399.99` | 其他 | 70 | -3.0 |
| `400–499.99` | 高消费占比 ≥ 34% | 90 | 0 |
| `400–499.99` | 其他 | 58 | -6.5 |
| `≥ 500` | 高消 ≥ 38% 且低消 ≤ 32% | 93 | 0 |
| `≥ 500` | 高消 < 25% 或低消 ≥ 45% | 32 | -10.5 |
| `≥ 500` | 其他 | 68 | -4.0 |

高消费占比 = 统一维度标签 `高` + `极高` 之和；低消费占比 = `低` + `极低` 之和。规则表在 `MATCH_CONFIG.spendingPower.bands`，**按顺序首次命中**，每个价格区间最后一条是无条件兜底。

## 4. 缺失语义（不插补）

| 情形 | 行为 |
| --- | --- |
| 任一侧缺某维度 / 该维度占比全为 0 | 该维度剔除，剩余维度**重归一化**；结果列出缺项与原因 |
| 该维度双方没有公共标签 | 维度不可用（`no-common-labels`），不参与加权；证据里列出被排除的单侧标签（切片 A · SA-06，相似度只在公共标签的重归一化分布上算） |
| 缺价格 | 消费能力维度剔除、**无惩罚**，标 `priceMissing`；**不继承抖音工具的 199 兜底价** |
| 渠道无该月画像 | 该组合不评分，列出原因 |
| 可用维度 < 3 | **不产出总分**，返回 `insufficient-dimensions`，看板标注「维度不足」 |
| 单品画像无月份 | 按静态事实画像使用，标 `productMonthUnknown` |
| 渠道画像为区间且覆盖所选月 | 可用，标 `channelApproximate` 与时间窗 |
| 月份不匹配 | **不回退**到相邻月份或相邻区间 |
| 同月多平台画像 | MCP 查询返回 `ambiguous` 并列出平台，`platform` 参数消歧；工具1 批量取用按显式优先级（抖音＞天猫＞京东）并在 notes 写明数量；不按平台名偷选 |
| 实体有多个月份画像且未指定 month | MCP 查询返回 `ambiguous` 并列出可用月份；`month` 入参必须是自然月 `YYYY-MM`，非法写法（含区间标签、`2026-13`）返回 `invalid-month`（core）／`invalid-argument`（MCP）／命令行非零退出 |

## 5. 配置与校验

`MATCH_CONFIG` 是唯一的参数来源，加载时校验：混合比例和为 1、六维权重齐全且为正、A > B > 熔断阈值、裁剪区间合法、价格带区间连续不重叠且每个区间有兜底、高／低消标签不重叠、版本号非空。**校验不通过直接抛错，不静默降级。**

当前版本：`sa-2026-11-common-labels-uncalibrated`（切片 A · SA-06 递增：相似度改为只在公共标签的重归一化分布上计算，技术修复非数据校准，仍记「未校准」）。

## 6. 工具1 命令行

```bash
npm run build

# 合成演示报告（无真实业务数据，可随站点发布）
npm run tool1 -- --demo --out site/web/tool1-report.html

# 抖音参考数据（只读，不复制不改写）
UOM_REFERENCE_ROOT="$HOME/工作/抖音货渠匹配/product/数据输入" \
  npm run tool1 -- --dataset reference --month 2026-10

# 本地 data/ 正式路径
npm run tool1 -- --dataset data --data-root data --month 2024-01
```

真实产物的输出目录默认在 `data/reports/tool1/<来源>-<月份>/`（已 gitignore），含三个文件：

| 文件 | 内容 |
| --- | --- |
| `index.html` | 自包含报告：矩阵、六维抽屉、错配清单、口径说明；零外网请求 |
| `mismatch.csv` | 错配清单全量（UTF-8 含 BOM，列顺序固定） |
| `match-results.json` | 全部单元的评分结果，便于审计与复算 |

## 7. 错配清单口径

```
错配优先级 = 零售额 × (1 - 匹配分/100)     降序
```

零售额是**商品级**指标，没有渠道级分解；该排序表示**组合调整优先级**，不代表该渠道的实际销售额。缺零售额的商品不进入排序，并在报告里列出原因。

## 8. 校验命令

```bash
npm run check                 # 类型检查 + 608 例单测（2026-11-28 切片 A 修正后实跑数）
npm run offline-check         # 断网守卫 + MCP 端到端 + 工具1 生成器断网（需真实数据，CI 记 NOT_RUN）
UOM_REFERENCE_ROOT=... npm run test:golden   # 黄金回归（本地，CI 不跑）
```

## 9. 数据边界

- 业务数据不出网：参考数据**只读**，不复制、不改名、不改写；真实产物只落 `data/reports/`。
- 仓库与 CI 不含任何真实业务数据；黄金回归在 CI 记为 `NOT_RUN`，本地运行并记录 SHA-256 证据。
- 站点只承载**合成演示数据**；真实数据版本不随站点发布。
