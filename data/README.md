## 归属键

**方案 A：款号（SPU）作为主键。**

- 商品主表用 `款号` 关联画像表
- 画像 CSV 的列名或目录名用款号标识
- 渠道标识与商品款号是不同命名体系，属正常；同一实体内命名需保持一致

## 目录说明

### `source/` —— 原始导出，原样放

按**渠道类型 → 实体 → 月份**组织，保留导出时的原始格式（不预先清洗、合并、改名）：

| 目录 | 放什么 |
| --- | --- |
| `source/brand/<YYYY-MM>/` | 品牌人群画像 |
| `source/live/<账号名>/<YYYY-MM>/` | 抖音直播账号画像 |
| `source/product-card/<店铺名>/<YYYY-MM>/` | 抖音商品卡店铺画像 |
| `source/short-video/<店铺名>/<YYYY-MM>/` | 抖音短视频店铺画像 |
| `source/tmall/<店铺名>/<YYYY-MM>/` | 天猫／京东店铺画像 |
| `source/offline/<门店名>/<YYYY-MM>/` | 线下门店画像 |
| `source/private-domain/<名称>/<YYYY-MM>/` | 私域小程序／特卖渠道画像 |
| `source/product-portraits/<款号>/<YYYY-MM>/` | 单品人群画像 |

月份目录名用 `YYYY-MM`（如 `2026-10`）。若导出文件名自带月份（如 `2610`），放进对应月份目录即可，解析层两种都认。

### `tables/` —— 宽表

一行一实体或一行的结构化表，CSV 或 XLSX 均可：

| 文件名 | 内容 | 必需性 |
| --- | --- | --- |
| `products.csv` | 商品主表：款号、名称、品类、季节、价格、零售额/量、毛利率等 | **必需** |
| `channels.csv` | 渠道层级对照：渠道标识、名称、类型、所属品牌、层级 | 必需（≥2 渠道时） |
| `product-attributes.csv` | 商品客观属性：版型、面料、工艺、IP | 建议（P2 用） |
| `aggregation.csv` | 品类／系列／爆款／IP 与商品的对应关系 | 可选 |
| `product-metrics.csv` | 单品经营指标：售罄率、退货率、毛利率、UPT、新老客占比、缺码率、UV、转化率 | 可选 |
| `channel-metrics.csv` | 渠道经营指标：成交额、件数、件单价、转化率、客单价 | 可选 |
| `funnel.csv` | 生命周期漏斗：按款按月的浏览/收藏/加购/购买/直接购买/退货 | 可选 |
| `member-features.csv` | 会员特征字典（业务方案 §5.2 字段集） | 可选 |

### `retention/` —— P3 报表预备

留存与回购数据（需求三）。当前阶段不处理，先放这里避免散落。

## 格式模板

**画像长表**（`source/` 下所有画像类文件）

```csv
标签类型,标签,SKU10001-占比,SKU10001-tgi
预测性别,男,2.04%,4.7737
预测性别,女,97.96%,233.8243
预测年龄段,18-19,1.51%,43.0421
```

标签类型至少覆盖六个统一维度：预测性别、预测年龄段、八大消费群体、预测消费能力、城市等级、预测人生阶段。
原始年龄段档位**不要提前归并**；TGI 缺失留空，**不要填 0**。

**商品主表表头**

```csv
款号,ID,商品名称,商品品类,二级品类,季节,吊牌价,企划件单价,零售额,零售量,件单价,零售折扣,经营毛利率,零售退款率,退货退款率,UV,转化率
```

**渠道层级对照表**

```csv
渠道标识,渠道名称,渠道类型,所属品牌,层级
dy_live_001,森马服饰号,抖音直播,森马,账号
dy_card_002,森马旗舰店,抖音商品卡,森马,店铺
```

## 缺失与冲突的处理原则

- 缺失维度**不插补**，显式标记为缺失
- 同款商品在不同平台的画像冲突**不隐式合并**，按显式映射表处理并记录来源
- 缺月**不回退**到相邻月份，MCP 查询时明确报错

具体口径在归一化规则文档 `docs/normalize-rules.md` 中定稿。
