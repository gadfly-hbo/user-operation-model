## 归属键

**方案 A：款号（SPU）作为主键。**

- 商品主表用 `款号` 关联画像表
- 画像 CSV 的列名或目录名用款号标识
- 渠道标识与商品款号是不同命名体系，属正常；同一实体内命名需保持一致

## 目录说明

> **填表用模板**：`templates/数据模板.xlsx`（每表一个 sheet，表头／必需性／口径／合成示例齐全）——把要填的 sheet 另存为单独 CSV／XLSX 放到对应路径即可（CSV 与 XLSX 均可）。

数据分三个区，**归一化层三个都读**：

```
data/
├── domains/     按业务域原样放（最自然，样例样本就是这个结构）
├── source/      按渠道维度 + 月份组织（适合多批次持续导出）
├── tables/      散表 / 宽表
└── retention/   P3 报表预备
```

| 文件名 | 内容 | 必需性 |

## 格式模板

**四平台的实际格式并不一致，归一化层按实际形态适配。**

**可直接填写的模板包**：`templates/数据模板.xlsx`——每张表一个 sheet，表头、必需／可选、口径、放到哪、合成示例齐全。把要填的 sheet **另存为单独的 CSV 或 XLSX**，放到该 sheet 第 1 行写的路径即可（CSV 与 XLSX 均可）。模板由代码契约生成（`npm run templates:build`），与下列表头同源。

本节表头已固化为代码契约（`packages/core/src/normalize/catalog/legacy-formats.ts`），由测试锁定与本节、模板包逐字一致；改表头请改契约后重新生成，**不要在本节手抄第二份**。

| 平台 | 列结构 | TGI |
| --- | --- | --- |
| 抖音 | `标签类型, 标签, <起止年月+实体名>-占比, <起止年月+实体名>-tgi` | 有 |
| 京东 | `标签名, 枚举值, 占比, TGI` | 有 |
| 天猫 | `标签类型, 一级标签(标签值), 占比` | **无** |
| 小红书 | 自然语言分析报告 | 正文散落，不可枚举 |

**抖音画像长表**（`source/` 与 `domains/07_人群画像/抖音/`；示例行为合成演示数据）

```csv
标签类型,标签,2601-2612演示账号1-占比,2601-2612演示账号1-tgi
预测性别,男,50.00%,100
预测性别,女,50.00%,100
```

标签类型至少覆盖六个统一维度：预测性别、预测年龄段、策略人群、消费能力、城市等级、预测人生阶段。
**原始年龄段档位不要提前归并**（三平台分档各不相同）；TGI 缺失留空，**不要填 0**。

**商品主表表头**（SKU 级，一款多行时按款号去重）

```csv
款号,ID,商品名称,商品品类,二级品类,季节,吊牌价,企划件单价,零售额,零售量,件单价,零售折扣,经营毛利率,零售退款率,退货退款率,UV,转化率
```

**商品客观属性表头**（款号级；工具2 预测输入只认客观属性）

```csv
款号,版型,面料,工艺,IP
```

**渠道层级对照表**

```csv
渠道标识,渠道名称,渠道类型,所属品牌,层级
D00001,演示账号1,抖音直播,演示品牌,账号
D00002,演示账号2,抖音商品卡,演示品牌,店铺
```

> 渠道主数据可直接用 `02_渠道信息/渠道店铺宽表.xlsx`（含平台、渠道类型、渠道等级、城市、门店状态与开店/关店时间），不必另建对照表。

## 缺失与冲突的处理原则

- 缺失维度**不插补**，显式标记为缺失
- 同款商品在不同平台的画像冲突**不隐式合并**，按显式映射表处理并记录来源
- 缺月**不回退**到相邻月份，MCP 查询时明确报错

具体口径在归一化规则文档 `docs/normalize-rules.md` 中定稿。
