## 归属键

**方案 A：款号（SPU）作为主键。**

- 商品主表用 `款号` 关联画像表
- 画像 CSV 的列名或目录名用款号标识
- 渠道标识与商品款号是不同命名体系，属正常；同一实体内命名需保持一致

## 目录说明

> **填表用模板**：`templates/数据模板.xlsx`（「使用说明」→「表目录」→ 各数据 sheet）——每个数据 sheet 第 1 行是表头、第 2 行是合成示例：**删除第 2 行示例、从第 2 行起填数据**，再按「表目录」写的**文件名规则与允许格式**另存到「放到哪」。哪些表 CSV／XLSX 均可、哪些只收一种格式（抖音仅 CSV；京东／天猫仅 XLSX 且 sheet 名固定；商品／渠道主数据仅 XLSX），以模板「表目录」为准。

数据分三个区，**归一化层三个都读**：

```
data/
├── domains/     按业务域原样放（最自然，样例样本就是这个结构）
├── source/      按渠道维度 + 月份组织（适合多批次持续导出）
├── tables/      散表 / 宽表
└── retention/   P3 报表预备
```

## 格式模板

**四平台的实际格式并不一致，归一化层按实际形态适配。文件名与 sheet 名是硬规则：不按规则命名的文件会被静默跳过（不报错、不生效）——唯一例外：抖音画像存成 XLSX 不是静默跳过，而是会让索引构建报错中断（见下方抖音硬规则）。**

**可直接填写的模板包**：`templates/数据模板.xlsx`——打开「使用说明」：每个数据 sheet 第 1 行是表头、第 2 行是合成示例；删除第 2 行示例、填入数据后，按「表目录」写的**文件名规则与允许格式**另存到「放到哪」。哪些表 CSV／XLSX 均可、哪些只收一种格式，以模板「表目录」为准。模板由代码契约生成（`npm run templates:build`），与下列表头同源。

本节表头与文件名／sheet 名硬规则已固化为代码契约（`packages/core/src/normalize/catalog/legacy-formats.ts`），由测试锁定与本节、模板包逐字一致；改契约请改代码后重新生成，**不要在本节手抄第二份**。

| 平台 | 列结构 | TGI |
| --- | --- | --- |
| 抖音 | `标签类型, 标签, <起止年月+实体名>-占比, <起止年月+实体名>-tgi` | 有 |
| 京东 | `标签名, 枚举值, 占比, TGI` | 有 |
| 天猫 | `标签类型, 一级标签(标签值), 占比` | **无** |
| 小红书 | 自然语言分析报告 | 正文散落，不可枚举 |

**平台硬规则**（与 catalog 契约逐字一致）：

- 抖音：文件名须以「_抖音.csv」结尾（后缀精确匹配，且优先于所在目录；只含「抖音」不够；文件名不参与实体／月份识别——实体与月份取自列名）；仅 CSV（抖音解析器按 CSV 文本读取；存成 XLSX 会导致索引构建报错中断，不是静默跳过）；sheet —（CSV 无 sheet）。**列名规则**：抖音画像长表例外：第 3／4 列列名必须改为「<起止年月><实体名>-占比」与「<起止年月><实体名>-tgi」（如 2601-2612演示账号1-占比）——抖音画像的实体名与月份取自列名，不是文件名或所在目录；不改列名会把画像全部静默归到模板演示实体「演示账号1」，实体名须与渠道店铺宽表「店铺」列一致。目录：`data/source/live/<账号名>/<YYYY-MM>/`、`data/source/product-card/<店铺名>/<YYYY-MM>/` 或 `data/domains/07_人群画像/抖音/`
- 京东：文件名须为「<起止年月><实体名>_京东.xlsx」形式：带月份与实体名且以「_京东.xlsx」结尾（如 2601-2612演示账号1_京东.xlsx；只含「京东」不够；实体与月份取自文件名，缺了会静默错挂到错误实体；后缀优先于所在目录，放 source/tmall/ 也会被识别为京东）；仅 XLSX（CSV 不被识别）；sheet 必须为 Sheet0。京东原生维度名：性别、年龄、十大靶群、购买力、城市线级。目录：`data/source/tmall/<店铺名>/<YYYY-MM>/` 或 `data/domains/07_人群画像/京东/`
- 天猫：文件名须为「<起止年月><实体名>_天猫.xlsx」形式：带月份与实体名且以「_天猫.xlsx」结尾（如 2601-2612演示账号1_天猫.xlsx；实体与月份取自文件名，缺了会静默错挂；后缀精确匹配，且优先于所在目录）；仅 XLSX（CSV 不被识别）；sheet 必须为 明细。目录：`data/source/tmall/<店铺名>/<YYYY-MM>/` 或 `data/domains/07_人群画像/天猫/`
- 小红书：Markdown 报告原文（.md）原样放 `data/domains/07_人群画像/小红书/`，无表格格式

**抖音画像长表**（`source/` 与 `domains/07_人群画像/抖音/`；示例行为合成演示数据）

```csv
标签类型,标签,2601-2612演示账号1-占比,2601-2612演示账号1-tgi
预测性别,男,50.00%,100
预测性别,女,50.00%,100
```

标签类型至少覆盖六个统一维度：预测性别、预测年龄段、策略人群、消费能力、城市等级、预测人生阶段。
**原始年龄段档位不要提前归并**（三平台分档各不相同）；TGI 缺失留空，**不要填 0**。

**商品主表表头**（SKU 级，一款多行时按款号去重；列名与字段目录 sources 对齐，放到 `domains/04_商品信息/`，文件名含「商品…信息表」或「商品宽表」；仅 XLSX）

```csv
款号,ID,商品名称,品类,中类,季节,吊牌价,零售额,零售量,件单价,零售折扣,经营毛利率,零售退款率,退货退款率,UV,转化率
```

**渠道店铺宽表表头**（放到 `domains/02_渠道信息/`，文件名含「渠道…宽表」或「店铺…宽表」；仅 XLSX；「店铺编码」是主键必需列，其余列可选，未列出的列也会收进 attributes 不丢数据）

```csv
店铺编码,店铺,渠道品牌,平台,渠道类型,渠道等级,一级渠道,二级渠道,省份,城市,城市级别,门店状态,开店时间,关店时间
D00001,演示账号1,演示品牌,抖音,抖音直播,核心店,内容渠道,品牌自播,上海,上海,新一线,营业,2024-01-01,
D00002,演示旗舰店,演示品牌,天猫,天猫旗舰,旗舰店,电商渠道,品牌旗舰店,浙江,杭州,新一线,营业,2024-01-01,
```

> **商品客观属性：当前无独立加载点，暂不需要单独提供。** P2 预测画像用的客观属性（品类／版型／面料／特殊功能/材质／IP 等）来自 `domains/04_商品信息/` 商品信息表里列名对应的列（字段目录映射见 `packages/core/src/product/catalog/fields.ts`），不单独成文件——单独的属性表文件名命中「商品…信息表」时会被当成第二张商品表，与真正的商品宽表冲突。

## 缺失与冲突的处理原则

- 缺失维度**不插补**，显式标记为缺失
- 同款商品在不同平台的画像冲突**不隐式合并**，按显式映射表处理并记录来源
- 缺月**不回退**到相邻月份，MCP 查询时明确报错

具体口径在归一化规则文档 `docs/normalize-rules.md` 中定稿。
