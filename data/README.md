## 归属键

**方案 A：款号（SPU）作为主键。**

- 商品主表用 `款号` 关联画像表
- 画像 CSV 的列名或目录名用款号标识
- 渠道标识与商品款号是不同命名体系，属正常；同一实体内命名需保持一致

## 目录说明

数据分三个区，**归一化层三个都读**：

```
data/
├── domains/     按业务域原样放（最自然，样例样本就是这个结构）
├── source/      按渠道维度 + 月份组织（适合多批次持续导出）
├── tables/      散表 / 宽表
└── retention/   P3 报表预备
```

### `source/` —— 按渠道维度 + 月份组织

| 目录 | 放什么 |

| `source/brand/<YYYY-MM>/` | 品牌人群画像 |
| `source/live/<账号名>/<YYYY-MM>/` | 抖音直播账号画像 |
| `source/product-card/<店铺名>/<YYYY-MM>/` | 抖音商品卡店铺画像 |

### `tables/` —— 散表与宽表

一行一实体或一行的结构化表，CSV 或 XLSX 均可：

| 文件名 | 内容 | 必需性 |

## 格式模板

**四平台的实际格式并不一致，归一化层按实际形态适配。**

| 平台 | 列结构 | TGI |
| --- | --- | --- |
| 抖音 | `标签类型, 标签, <起止年月+实体名>-占比, <起止年月+实体名>-tgi` | 有 |
| 京东 | `标签名, 枚举值, 占比, TGI` | 有 |
| 天猫 | `标签类型, 一级标签(标签值), 占比` | **无** |
| 小红书 | 自然语言分析报告 | 正文散落，不可枚举 |

**抖音画像长表**（`source/` 与 `domains/07_人群画像/抖音/`）

```csv
标签类型,标签,2507-2606森马某店-占比,2507-2606森马某店-tgi
预测性别,男,39.26%,90.62089851674344
预测性别,女,60.74%,144.1153984073459
预测年龄段,18-19,2.79%,93.73368817435292
```

标签类型至少覆盖六个统一维度：预测性别、预测年龄段、策略人群、消费能力、城市等级、预测人生阶段。
**原始年龄段档位不要提前归并**（三平台分档各不相同）；TGI 缺失留空，**不要填 0**。

**商品主表表头**（SKU 级，一款多行时按款号去重）

```csv
款号,ID,商品名称,商品品类,二级品类,季节,吊牌价,企划件单价,零售额,零售量,件单价,零售折扣,经营毛利率,零售退款率,退货退款率,UV,转化率
```

**渠道层级对照表**

```csv
渠道标识,渠道名称,渠道类型,所属品牌,层级
dy_live_001,某抖音直播号,抖音直播,某品牌,账号
dy_card_002,某抖音商品卡店,抖音商品卡,某品牌,店铺
```

> 渠道主数据可直接用 `02_渠道信息/渠道店铺宽表.xlsx`（含平台、渠道类型、渠道等级、城市、门店状态与开店/关店时间），不必另建对照表。

## 缺失与冲突的处理原则

- 缺失维度**不插补**，显式标记为缺失
- 同款商品在不同平台的画像冲突**不隐式合并**，按显式映射表处理并记录来源
- 缺月**不回退**到相邻月份，MCP 查询时明确报错

具体口径在归一化规则文档 `docs/normalize-rules.md` 中定稿。
