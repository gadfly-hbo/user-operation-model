## 逐项核对结论

### A. 按规格验收条目逐项核对

#### A-1 DM15「跨平台标签映射表逐条可追溯 / 未声明组合不自动推断 / 泛人群与服饰体系互转被显式禁止并有测试覆盖」

**结论：部分 —— 划分基本诚实，但「禁止互转已由测试强制」不成立（阻断 B1）。**

| 子项 | 结论 | 依据 |
| --- | --- | --- |
| 逐条可追溯（来源平台、源标签、目标维度、目标标签） | **PASS** | `TagMapping` 含 `id/platform/sourceDimension/sourceLabel/targetDimension/targetLabel/confidence/status`；77 条全部非空（S1/S4） |
| 未声明的组合不自动推断 | **PASS** | `MappingTable.resolve()` 以「平台+源维度+源标签」精确查表，未命中即返回 `undefined`；`needs-confirmation` 条目不参与 `resolve()`（有测试断言） |
| 泛人群 ⇄ 服饰体系互转被显式禁止 | **FAIL（数据层当前满足，机制层缺失）** | 数据层：泛人群源维度（八大消费群体/大快消策略人群/十大靶群）无一条指向 `apparel_segment`，服饰源维度也无一条指向 `strategy_segment`（实测 0 条）。机制层：`DimensionSpec`/`MappingTable` 无任何跨体系禁配约束，唯一约束来自两套词表**字面无重名** |
| 该禁止有测试覆盖 | **FAIL** | `core.test.ts`「泛人群体系与服饰体系禁止互转」只断言「映射目标标签不出现在对方词表」。实测注入违禁互转映射（`大服饰策略人群/潮流人群 → strategy_segment/都市蓝领`）后：`MappingTable.validate()` 返回 `[]`、`conflicts()` 返回 `[]`、该测试断言**全部通过**、`resolve()` 直接返回该违禁映射。即测试只覆盖「词表无重名」，不覆盖「禁止跨体系映射」 |

诚实性判断：result.md 把 DM15 标为「部分」并说明「投影执行属 P0-4」是**诚实的**；但同一行断言「『禁止互转』已由测试强制」是**不成立的保证**，必须修正。

#### A-2 DM16「年龄段归并结果附 precisionLoss 标记，原始分档在 platformLabels 中完整保留」

**结论：部分 —— 划分诚实，规则本身有事实错误与不对称标记（阻断 B2）。**

| 子项 | 结论 | 依据 |
| --- | --- | --- |
| 覆盖三平台全部源档位 | **PASS** | 32 条规则 ↔ 抖音 10 + 天猫 9 + 京东 13，逐一命中真实枚举，无漏档（S2/S3） |
| 归并结果附精度标记的**数据结构** | **PASS** | `BandRule.precision`（exact/partial/lossy/unmapped）＋ `spill`；`PortraitProjection.precisionLoss` / `lossySources` 已在类型层就位（写入属 P0-4） |
| 原始分档完整保留 | **PASS** | `Portrait.platformLabels` 为必填的平台原值分组，投影不覆盖它（C1 结构支持） |
| 精度标记的正确性 | **FAIL** | ① `jd/16~20岁` 标记 `spill: '24-30'`，但源区间 [16,20] 与 24–30 **无交集**——该档 16–17 岁是**低于**统一下界，不是落入 24–30，其 `note` 与 `spill` 自相矛盾；② 50 岁口径冲突只标了天猫一侧：`tmall/[50,54]` 标 `partial`，而 `douyin/46-50`（note 已写明冲突）标 `exact`、`jd/46~50岁` 标 `exact` 且无任何说明；③ `age-bands.ts` 文件头注释称「规则中如实标记 partial」，与数据自相矛盾。按统一目标档定义（含 50 岁），抖音 46-50 与京东 46~50 各含 1 个争议年份，与天猫同样存在精度损失 |

诚实性判断：result.md 称 32 条规则「均带 `precision` 与 `spill`/`note`」属实（实测 6 条 partial 均带 spill+note，1 条 unmapped 带 note）；但「精度标记正确」这一隐含保证不成立。

**B1 · DM15「泛人群 ⇄ 服饰体系禁止互转」实际上没有被强制，且 result.md 给出了不成立的保证**

- 位置：`packages/core/test/core.test.ts`「泛人群体系与服饰体系禁止互转」；`packages/core/src/portrait/registry.ts` 的 `MappingTable.validate()`；`openspec/changes/data-mcp-core/result.md` §3（DM15 行）
- 问题：该测试只断言「映射目标标签不出现在对方词表」，即只覆盖**词表字面无重名**。它无法阻止**跨体系映射**（服饰体系源标签映射到泛人群维度或反之）。规格 DM15 明确要求「泛人群体系与服饰体系的互转被显式禁止**并有测试覆盖**」，result.md 亦称「『禁止互转』已由测试强制」。
- 证据（可复现）：向 `MappingTable` 注入 `大服饰策略人群/潮流人群 → strategy_segment/都市蓝领`（status `confirmed`）后——`validate(registry)` 返回 `[]`；`conflicts()` 返回 `[]`；该测试的全部断言**通过**；`resolve('tmall','大服饰策略人群','潮流人群')` 直接返回这条违禁映射。当前数据中无违禁映射，故今日无运行时损害，但**后续任何人新增一条映射都会绿灯通过**，背对背之外的「体系不互转」约束形同虚设。
- 建议：在 `MappingTable` 增加体系级禁配约束（例如 `DimensionSpec` 增加 `family`/`conversionAllowed` 字段，或在 `MappingTable.validate()` 中按「源维度族 ≠ 目标维度族」硬校验），并把测试改为**行为断言**（注入违禁映射 → 断言 `validate()`/`add()` 抛错或拒绝），同时修正 result.md §3 的表述。

**B2 · 年龄归并规则存在事实错误，且 50 岁口径冲突只标了一半**

- 位置：`packages/core/src/portrait/catalog/age-bands.ts`（`jd/16~20岁` 条目、`douyin/46-50` 条目、`jd/46~50岁` 条目、文件头注释）
- 问题与证据：
  1. `jd/16~20岁` 标 `precision: 'partial', spill: '24-30'`。源区间 [16,20] 与统一档 24–30 **无任何交集**；该档的精度损失来自 **16–17 岁低于统一下界 18**，条目自带的 `note` 也写的是「16-17 岁不在统一档位范围内」，与 `spill` 互相矛盾。同一文件的 `jd/21~25岁` 才是真正跨越 24–30（25 岁落入）。
  2. 50 岁口径：抖音 46–50 计入 `41-50`、天猫 [50,54] 计入 `50+`，两者不可调和。候选只在**天猫一侧**打了 `partial`，抖音 `46-50` 标 `exact`（仅 note 提及）、京东 `46~50岁` 标 `exact` 且**无任何说明**；而 `age-bands.ts` 文件头却写「规则中如实标记 partial，不做人为统一」——注释与数据自相矛盾。后果：DM16 的 `precisionLoss` 信号在三个平台之间**不对称**，同一份 50 岁人群在抖音/京东记录上不触发、在天猫记录上触发，跨平台可比性无法保证。
- 建议：① 修正 `jd/16~20岁` 的 `spill`（应为空并说明低于下界，或显式定义「下溢」机制）；② 统一 50 岁冲突的表达方式——要么三平台相关规则统一标 `partial` 并在 `note` 互相指认，要么把「跨平台口径冲突」与「档内边界溢出」拆成两个独立标记（现结构只有一个 `precision` 字段承载两种语义）；③ 同步修正文件头注释。
