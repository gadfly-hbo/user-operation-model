## 4. 数据契约

以讨论稿 §7 为初稿，实现时在 `packages/core/src/portrait/types.ts` 与 `packages/core/src/product/types.ts` 落地。**类型定义是单一来源**，MCP 与后续工具1／工具2／报表共用。

```ts
type PortraitLabel = { share: number; tgi?: number };

type Portrait = {
  entityType: 'product' | 'channel' | 'brand' | 'category' | 'series' | 'ip' | 'competitor';
  entityId: string;
  month: string;
  dimension: string;
  labels: Record<string, PortraitLabel>;
  sampleSize?: number;
  coverage?: number;
};
```

### 4.1 修正 C1：画像双层结构

依据[数据样本评估 §4.2](../../../docs/data-source-review.md#42-策略人群三套命名同源异名--一套独立体系)，三平台的策略人群与年龄段分档互不相同且命名各异，**平台原生标签必须保留，投影不可逆**：

```ts
type Portrait = {
  // ...上列字段
  platformLabels?: Record<string, Record<string, PortraitLabel>>;  // 平台原值，完整保留
  projections?: Record<string, {                              // 统一维度投影
    dimension: string;
    labels: Record<string, PortraitLabel>;
    precisionLoss?: boolean;   // 归并造成的精度损失标记
  }>;
};
```

- `platformLabels` 键为平台标识（douyin / tmall / jd / xhs）
- `projections` 键为统一维度名，映射关系**显式声明、逐条可追溯**，登记在归一化规则文档
- **不自动推断未声明的映射**；泛人群体系（大快消策略人群／八大消费群体／十大靶群）与服饰体系（大服饰策略人群）**禁止互转**
- 投影**不删除** `platformLabels`，任何投影值都能回溯到源标签与源平台

### 4.2 修正 C2：匹配分的计算空间

天猫画像**无 TGI**（仅占比）。因此：

- 匹配分**首版在 share 空间计算**，保证三平台口径一致
- TGI 作为**独立增强信息**单独标注，并按平台可比性分级（京东／抖音可算，天猫不可算）
- 讨论稿 §4.1 中「升级为 TGI 空间计算」的建议在本轮**不采用**，P1 校准阶段以「平台内 TGI 一致性」检查补偿

### 4.3 修正 C3：年龄段归并

统一目标 5 档：`18-23 / 24-30 / 31-40 / 41-50 / 50+`。三平台原始分档（抖音 10 档 / 天猫 9 档 / 京东 13 档）**原样保留**，投影时附 `precisionLoss` 标记边界误差档位。

### 4.4 修正 C4：背对背隔离的字段清单

依据[数据样本评估 §8.1](../../../docs/data-source-review.md#81-背对背隔离的具体字段清单)，工具2 预测路径**排除**以下人工定位字段：

`年龄段`、`商品定位`、`推广群组`、`商品群`、`场景`、`延续款`、`主题`、`故事线`

**允许**用于预测的客观属性：`货品分类`、`款属性`、`产品链（大类）`、`中类`、`小类`、`年份`、`季节`、`产品季`、`性别`、`吊牌价`、`全域款`、`O2O`、`新老品`、`SKU/SKC/条码`、平台商品 ID 与链接，以及 ModelEvol 建模表的全 23 列。

**`性别修正` 单独判定**：属从历史成交回算的事实修正而非人工画像。新款预测**不得使用该款自身的修正值**，应从同类历史款推算（ModelEvol v0.6 既有做法）。

此约束在类型层面以字段可见性控制落实，并经独立复核确认。

`ProductDossier`、`DimensionDiff`、`MatchResult` 见讨论稿 §7.2–§7.4，本轮只落地前两项。

### 双层状态：接口就绪 ≠ 数据就绪

每个工具的交付状态分两层，**分别报告，不合并表述**：

| 层 | 含义 | 判定 |
| --- | --- | --- |
| **接口** | MCP 工具已注册、参数契约完整、返回结构确定 | 工具可在 MCP 客户端中被发现与调用 |
| **数据** | 该工具所需的数据源已接入，能返回真实结果 | 数据在 `data/` 中存在且能被归一化层解析 |

**数据未就位的工具**返回**明确错误**并说明缺什么数据源，**不返回空结果**——与 DM13 的口径一致（空结果与数据缺失必须可区分）。

首版状态：**9 个工具数据就绪，8 个数据未就位**。数据是否就绪由**数据目录探测**决定（`packages/core/src/index/build.ts` 的 `DATA_SOURCE_PROBES`），文件到位后自动可用，不需要改代码。

## 7. 关键边界

| 边界 | 规则 |
| --- | --- |
| 数据只读 | 数据目录只读挂载；任何写入只落 `.local/`（已 gitignore）或显式输出目录 |
| 不出网 | 归一化与 MCP 运行期**零网络请求**；不引入带遥测或云 API 的依赖 |
| 传输 | MCP 仅 stdio，不监听端口，不做鉴权 |
| 缺失语义 | 缺失维度**不插补**，进 registry 显式标记（继承 ModelEvol v0.7 缺失语义处理） |
| 月份缺失 | 缺月**不回退**到相邻月份，查询时明确报「该实体在 X 月无画像」；**P1 匹配计算取「最近可用月」的口径在 P1 单独定义**，不污染 MCP 层 |
| 部分历史 | 用户声明的覆盖范围即为处理边界，范围外的月份与实体**不推测、不填充** |
| 跨平台 | 标签映射必须显式声明，**禁止隐式合并**（ModelEvol v0.5「同款优先抖音画像」导致渠道语义混淆，本项目不继承） |
| 维度单一来源 | 维度定义只在 `packages/core` 一处，MCP 不得自建维度名 |
| TGI 语义 | TGI 相对何种基准须在规则文档写明，不得隐式假定为大盘 |
