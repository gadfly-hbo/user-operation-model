- 基线：`main` @ `9ac886c`（P1 已合并）
- `data/` 现状：334 款商品、200 个渠道、**7 份画像**；200 个渠道中**只有 1 个**能关联到画像（实体名全称 vs 渠道宽表简称不一致）

- **新发现（本轮核实，纠正 P0 记录）**：8 个未就绪工具中，**7 个的 MCP 处理器是纯桩**（`packages/data-mcp/src/server.ts` 里无条件 `return notReady(...)`）：竞品画像、漏斗、会员特征、Cohort、Recency、流转矩阵、三大诊断。**「探测到文件即自动可用」对这 7 个不成立**——文件到位也不会可用，必须先实现解析器。只有 `get_brand_portrait` 是「探测 + 真实实现」。

- DM04（跨文件冲突显式映射）NOT_RUN：当前单文件场景不触发，多批次数据到位后必须补。

## 3. 验收条目

### 阶段一（不依赖真实数据，合成 fixture 即可验证）

| 标识 | 验收条目 |
| --- | --- |
| DC01 | 7 个占位工具改为真实实现：合成数据文件到位时返回真实解析结果；文件缺失时**仍**返回 `data-not-ready` 并说明缺哪个文件，**不返回空结果** |
| DC02 | 每个新解析器有错误路径测试：空文件／只有表头／缺必要列／占比或数值列不可解析 → 抛 `NormalizationError`，不静默空结果（继承 DM13 口径） |
| DC03 | **探测表与处理器一致性守卫**：对 `DATA_SOURCE_PROBES` 里的每个工具，合成 fixture 满足探测条件时，MCP 处理器**不得**返回 `data-not-ready`。该测试锁死「探测说就绪但处理器是桩」这类缺陷 |
| DC04 | 实体别名目录：`data/tables/entity-alias.csv` 存在时，画像实体名经别名归一到规范名后再关联渠道宽表；不存在时行为与现状逐字一致；别名逐条可追溯（规范名、别名、店铺编码、平台） |
| DC05 | 跨文件冲突显式映射：`data/tables/portrait-conflicts.csv` 存在时按表处理同款多平台画像冲突；不存在且出现冲突时保持现状（记 conflict issue、保留先到一条、**不隐式合并**） |
| DC06 | README 时间范围声明：填写后索引只覆盖声明的月份／渠道／商品范围，范围外内容记 issue 并跳过；未填写时保持现状（覆盖全部扫描结果）并在索引里记录「未声明」 |
| DC07 | 商品↔渠道关联：`data/tables/product-channel.csv` 存在时 `list_products` 的 `channel` 过滤可用，且错配清单可输出渠道级销售额；不存在时返回 `data-not-ready`（现状） |
| DC08 | 聚合层级：`data/tables/aggregate-groups.csv` 存在时 `get_portrait_aggregate` 支持 `series`／`hot`／`ip`；不存在时仅 `category`（现状），聚合口径沿用规则文档 §5.6 |
| DC09 | 经营指标接入：`product-performance.csv`／`channel-performance.csv` 存在时填充 `ProductDossier.performance` 与渠道经营字段；**缺失字段保留缺失标记，不插补**；零售额/零售量齐全时推出真实成交单价 |
| DC10 | 不新增第三方依赖；CSV 走既有解析器、XLSX 走 exceljs；新代码零出网 |
| DC11 | 跨平台新标签／新维度必须登记映射表才参与投影；未登记不自动推断（继承 DM15） |

## 4. 数据契约（新增表结构）

所有新表**列名以要数清单为准**；解析器对多余列忽略、对缺失列按「缺失不插补」处理。

```
entity-alias.csv        规范实体名, 别名, 店铺编码, 平台
portrait-conflicts.csv  款号或实体, 月份, 平台A, 平台B, 处置（keep-a | keep-b | manual）, 说明
product-channel.csv     款号, 店铺编码, 月份, 零售额, 零售量
product-performance.csv 款号, 月份, 零售额, 零售量, 售罄率, 退货率, 退款率, 毛利率, UV, 转化率
channel-performance.csv 店铺编码, 月份, 成交额, 成交件数, 转化率, 客单价, 毛利率
aggregate-groups.csv    款号, 系列, 爆款组, IP
funnel.csv              款号, 月份, 阶段（launch|growth|clearance）, 浏览, 收藏, 加购, 购买, 直接购买, 退货
member-features.csv     按业务方案 §5.2 字段集
cohort.csv / recency.csv / channel-flow.csv / diagnosis.csv / monthly-mix.csv / clearance-leap.csv
                        按要数清单的口径列
```

**口径以《指标字典-品牌经营业务》为准**：售罄率、退货率、退款率、毛利率取字典中的指标编码，登记在归一化规则文档；业务侧未确认编码前，解析器按列名直读并在结果里标注「口径待确认」。

## 7. 关键边界

| 边界 | 规则 |
| --- | --- |
| 探测与实现绑定 | 探测表里登记的每个数据源，必须有非桩处理器；一致性守卫测试锁死 |
| 缺失语义 | 缺文件 → `data-not-ready` 并说明缺什么；缺列/缺值 → 缺失标记，**不插补**；坏输入 → 抛错，不静默空结果 |
| 不猜口径 | 5 条业务口径未确认前，解析结果标注「口径待确认」，不自行裁定 |
| 别名不隐式合并 | 别名只做「实体名归一」，不做画像内容的合并；冲突按显式映射表或现状保留先到一条 |
| 数据不出网 | 新解析器零出网；合成 fixture 才可入库，真实数据只落 `data/` |
| 单一来源 | 指标口径登记进归一化规则文档；映射登记进映射表；不在代码里写死标签词表 |
